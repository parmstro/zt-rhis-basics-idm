== Welcome to Module 4

In this module you will run the play that installs and configures your IdM Primary.
For this configuration there is no real difference between and IdM Primary and an IdM Replica.
They end up being identical deployments. 
The only real difference is order of operations.
As you continue to configure roles, as an example, Active Directory Trusts, there are steps to take to maintain symmetry.
More on that later.

=== The model for the build

A mentioned in the introduction, RHIS was designed to be capable of building an entire Red Hat Infrastructure from zero implementation.
This is the primary reason for the rhis-provisioner container.
The container delivers all the binary dependencies, python dependencies, ansible collections and ansible code needed in a self contained package.
This minimizes the setup required to get started.

It is assumed that Ansible Automation Platform does not exist.
All the Day 1 build operations are performed via the container.
Once we have "Bootstrapped" the environment, AAP can take over and build out the remainder of the environment.

By bootstrap, we mean creating your Provisioner node, then creating an IdM Primary and a Satellite Primary. 
If IdM, Satellite, or AAP already exist, rhis-provisioner configuration can adjust to this and add only the portions that are needed.
We still run the initial steps from the provisioner.

=== Finishing Touches

Due to the nature of the lab environment, there are a couple of additional steps that need to take place to make the IdM Web UI available.

Please perform the next steps as root using the idm1 tab.
The root user is already logged in.

Select the idm1 tab.

[source, bash]
----
cd /root
ls ipa-web.sh
----

You should see the script.

Execute the ipa-web.sh script.

[source, bash]
----
./ipa-web.sh
----

You should see the following output.

```
[root@idm1 ~]# ./ipa-web.sh 
# VERSION 7 - DO NOT REMOVE THIS LINE

RequestHeader set Host idm1.example.local
RequestHeader set Referer https://idm1.example.local/ipa/ui/
RewriteEngine on

# Rewrite for plugin index, make it like it's a static file
RewriteRule ^/ipa/ui/js/freeipa/plugins.js$    /ipa/wsgi/plugins.py [PT]

RewriteCond %{HTTP_HOST}    ^ipa-ca.example.local$ [NC]
RewriteCond %{REQUEST_URI}  !^/ipa/crl
RewriteCond %{REQUEST_URI}  !^/(ca|kra|pki|acme)
[root@idm1 ~]#
```
This script modifies the returns, etc.. that are sent by IdM so that the frame in your lab window renders the web pages properly.
This typically does not need to be done in production. 

There is an additional script that we will run to make sure that our local networks are trusted for recursion.

Again, using the idm1 tab as root.

Select the idm1 tab.

[source, bash]
----
cd /root
ls trustednetwork.sh
----

You should see the script.

Execute the script.

[source, bash]
----
./trustednetwork.sh
----

You should see the following output

```
[root@idm1 ~]# ./trustednetwork.sh 
acl "trusted_network" { 
    localnets; 
    localhost; 
    192.168.0.0/24; 
};
allow-recursion { trusted_network; };
allow-query-cache  { trusted_network; };
dnssec-validation yes;
[root@idm1 ~]#
```

This backs up and then updates the named extensions for Red Hat IdM in the following files.

- /etc/named/ipa-ext.conf
- /etc/named/ipa-options-ext.conf
